# Agent 与 Skill

这些是教学答法；具体软件操作使用时核验。按需结合用户事实，不逐条盘问。[依据说明](../sources.md)。

## F22｜模型、Agent、Skill 到底谁在回答我？〔P0〕

回答通常由宿主使用的模型生成；Agent 组织任务并调用可用工具；Skill 提供方法和参考资料。安装 Skill 不会自动更换模型，也不会自动获得工具权限。

下一步：用当前任务辨认“谁生成、能用什么工具、参考什么资料”。成功信号：能说明 Skill 是怎么帮助回答的。依据：S02、S08、S09。

## F23｜你的 Skill 的知识从哪来？会不会瞎编胖叔的经验？〔P0〕

发布包内应附经筛选、获准使用的教学内容和来源说明；模型也会用通用知识组织表达。必须区分胖叔方法、引用资料、模型解释和未核验信息，不能说每句话都来自胖叔。

下一步：遇到关键结论可问“依据是什么”。成功信号：能找到对应资料或明确标为通用解释/建议。依据：L03、U01；产品要求。

## F24｜我安装了怎么没反应？怎么知道调用成功？〔P0〕

先确认宿主是否支持这种 Skill、安装范围及当前对话是否加载；不要把下载了 ZIP 等同于调用成功。

下一步：按该宿主已验证的说明显式调用，并运行标准小任务；若可见加载记录，一并查看。成功信号：不仅列出名字，还按包内参考材料完成指定任务。依据：S08、S09；验收设计。

## F25｜任何聊天软件都能装吗？不能装还能学吗？〔P0〕

不是所有聊天产品都支持目录形式的 Skill。可提供独立入门提示词和短讲义作为降级方案，但它不等于完整安装，也不能承诺同样的文件和执行能力。

下一步：识别宿主；支持则用经过验证的安装路径，不支持则进入简版学习。成功信号：用户清楚当前可用能力，能做第一项练习。依据：S08；降级方案为产品设计。

## F26｜装了 Skill，为什么还不能上网、看图或者替我点按钮？〔P0〕

这些能力取决于宿主、模型、连接工具和授权。教程不能凭文字凭空增加权限。

下一步：检查当前是否有对应能力；没有则请求用户提供文字材料或自行完成界面操作。成功信号：不假装看到了图片、网页或已完成点击。依据：S02、S08、S09。

## F27｜什么时候需要知识库、RAG、Workflow、API、MCP？〔P1〕

重复步骤再考虑 Workflow，长期资料检索考虑知识库/RAG，程序调用服务涉及 API，连接外部工具时再理解 MCP。先看当前任务是否真的需要。

下一步：从实际瓶颈只解释一个相关概念。成功信号：能说清它解决什么问题；不把术语全套作为入门门槛。依据：L03、S09；RAG 不保证回答正确。
