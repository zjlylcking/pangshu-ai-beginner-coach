# 资料与可信度

这些是教学答法；具体软件操作使用时核验。按需结合用户事实，不逐条盘问。[依据说明](../sources.md)。

## F15｜我上传文件了，为什么它说找不到或者乱回答？〔P0〕

上传成功不等于正文已被模型读取。可能是文件不可访问、格式解析失败、图片型文档或只读到部分内容，需查看实际证据。

下一步：当前 Agent 有文件读取能力时，先让它自行打开并引用相关页或段落，再与你的原文核对；若当前 Agent 确实读不到，才请用户贴相关文字、清晰截图或报错。不能只靠它口头说“已读”。成功信号：关键回答能对应实际原文。依据：S03、S05；读取验收为产品设计。

## F16｜文章、截图、网址，应该发哪一种？〔P0〕

文字便于准确引用，截图适合界面和视觉问题，网址需要当前工具能访问。只提供与问题相关的材料。

下一步：界面卡住发清晰截图；报错能复制就附原文；链接打不开则粘贴有权限分享的段落。成功信号：教练获得了可辨认的事实。依据：S01、S03、U01。

## F17｜文件越多越好？能不能把电脑资料全塞进去？〔P1〕

先给当前任务需要的资料。过多无关内容会增加查找负担，也可能暴露不必要的信息。

下一步：选一份主材料和少量必要参考。成功信号：能指出每份材料与任务的关系。依据：S01、S03。

## F18｜聊久了它忘记要求，新对话又不知道我做过什么？〔P0〕

可见上下文和产品记忆都有边界，不能默认跨对话完整保留。

下一步：生成交接卡：目标、已完成、当前版本、关键限制、失败记录、下一步。成功信号：新对话能基于这些事实继续，未重复已排除方案。依据：S03。

## F19｜怎么知道答案是不是编的？叫它自查就够了吗？〔P0〕

自查不能替代外部证据。数字、引文和时效事实要回到原文；代码和功能要实际测试。

下一步：抽查一个关键主张的来源，或用已知输入测试结果。成功信号：结论得到独立核对；查不到的明确标未核实。依据：S02、L01、C02；验收设计。

## F20｜同一个问题怎么每次答案不一样？〔P1〕

模型输出可能变化，上下文、版本、工具结果也会改变。应比较是否达到相同标准，而非文字是否完全一样。

下一步：固定材料、要求和检查标准对照两次结果。成功信号：识别事实错误与合理表达差异。依据：S02。

## F21｜公司资料、客户信息和 API Key 能直接发吗？〔P0〕

先确认有权分享、平台数据处理规则和实际必要性；练习用脱敏资料，不在提示词、公开截图或前端代码里放密钥。

下一步：遮盖凭证和个人信息，保留错误类型及必要结构。成功信号：仍能分析问题，未暴露敏感值。依据：S04、L01；边界按具体组织规则处理。
