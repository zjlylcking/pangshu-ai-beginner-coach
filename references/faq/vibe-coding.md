# 应用与分享

这些是教学答法；具体软件操作使用时核验。按需结合用户事实，不逐条盘问。[依据说明](../sources.md)。

## F33｜不会写代码，真能做一个应用吗？〔P0〕

可以从目标小、风险低的工具开始，借助 Agent 生成和修改代码；能否可靠使用仍取决于测试和维护。

下一步：选待办清单、单位换算或文字整理中的一个最小功能。成功信号：完成一次输入到输出的实际操作。依据：S04、L03；不承诺零知识做任何系统。

## F34｜我想做一个“什么都有”的系统，从哪开始？〔P0〕

先保留一个用户、一类输入和一个核心结果。登录、支付、多角色等放到确有需要且能验证的后续阶段。

下一步：写“谁遇到什么问题，第一版只完成什么”。成功信号：一页 PRD 能列清做与不做、输入输出和验收。依据：S01、L03。

## F35｜为什么要先写 PRD？会不会太麻烦？〔P1〕

PRD 是把想法变成可检查约定。小练习可以只写一页或几段，已有清楚要求时不用再重复访谈。

下一步：确认目标、一个核心功能和成功条件。成功信号：能据此判断第一版是否做对。依据：S01、L03；PRD 格式为教学设计。

## F36｜AI 给我一堆代码，往哪放、怎么打开？〔P0〕

先判断交付的是单文件、完整项目还是平台内应用。要求 Agent 按当前环境给文件位置、启动方式和访问入口，而不是默认用户懂终端。

下一步：让它指出当前产物在哪里和下一步操作。成功信号：用户打开的是实际运行结果，能操作核心功能。依据：产品假设、L03、C01。

## F37｜页面看起来挺好，为什么按钮没用、刷新数据就没了？〔P0〕

页面外观、交互、数据保存是不同事项。临时内存、浏览器本地保存和服务器存储的效果不同，先问清期望再选方案。

下一步：添加一条数据，点击、刷新、关闭重开，再说明是否需要另一台设备访问。成功信号：结果符合约定，不把本机保存说成多人同步。依据：S07、L03；测试流程为设计。

## F38｜越改越坏怎么办，能回到上一个能用的版本吗？〔P0〕

每完成一个可用小功能就保存可恢复版本；回退前看哪些代码和数据受影响。代码回退不一定恢复数据库。

下一步：先保留当前改动，定位最后可用版本，按授权恢复并测试。成功信号：可用功能恢复，新内容没有被无说明地丢弃。依据：S01、S04、C01。

## F39｜我的电脑能打开，为什么朋友打不开？〔P0〕

本地地址、临时预览和正式公开地址不同。分享前需确认链接类型、访问权限和服务是否持续运行。

下一步：识别当前地址；准备分享时在另一设备或独立浏览器验证访问与核心功能。成功信号：接收者能按说明打开并完成任务。依据：S06、S07、L03。

## F40｜做到什么程度算学会，可以分享了？〔P0〕

理解概念、自己做成、别人能用是不同层次。不能用“生成了一页代码”代替应用完成。

下一步：基础任务核对原文与结果；应用测试正常、空白、错误输入和重复操作；分享还需独立环境验证。成功信号：能说明通过了什么、未验证什么，换个相似任务还能做。依据：L03、S02、S07；评价规则为设计。
