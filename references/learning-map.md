知识地图不是必修顺序：从学员目标切入，缺什么补什么。系统学习先给全景和当前任务，不罗列工具全家桶。

| 模块 | 内容 | 学习证据 |
|---|---|---|
| M01 认识与起步 | AI 用途、局限、现有入口、核验 | 选择低风险任务并说明人的责任 |
| M02 需求与提示词 | 目标、材料、结果、约束、反馈 | 可执行需求与具体修改 |
| M03 资料与上下文 | 文件、截图、链接、来源和交接 | 原文可追溯结果与交接卡 |
| M04 日常交付 | 文字、纪要、表格、文档、PPT | 可打开、检查、必要时编辑的作品 |
| M05 质量与排错 | 事实、结构、视觉、功能、截图和模型比较 | 修改对照与复验 |
| M06 工具与复用 | 模型/Agent/Skill、模板、稳定方法 | 实际调用效果或可复用任务方法 |

## 基础讲义：遇到相关问题再解释

- **AI** 是一大类技术。本课关注能处理输入并生成内容的生成式 AI；“像助手”是使用比喻，不意味有人的责任或理解。
- **大模型** 是处理和生成内容的核心组件，依据训练所得规律和当前可见信息生成回答，不是每句都从教材原样查出。流畅不保证正确。
- **多模态** 是文字、图像、音频等不同输入输出能力。产品不一定开放模型全部能力，能聊天不代表能看图。
- **Prompt** 是任务说明，常含目标、材料、产出和限制，不需要背咒语。
- **上下文** 是当前能用于回答的信息，包括指令、相关历史、实际读到的文件与工具结果。相关比数量重要。
- **Token** 是处理内容的计量单位，不等于固定字数，会影响上下文容量和部分计费。新手先保持材料相关，不必先研究换算。
- **幻觉** 是生成了错误或无依据的信息。自查不能替代原文、可靠来源与实际测试。模型也可能迎合用户前提，人仍需判断。
- **Agent** 通常由模型结合工具、状态与执行机制组成，能推进多步任务。工具和权限决定能访问或改变什么。
- **Skill** 是可复用方法与资源的封装，可包含指令、模板、脚本。它不能保证模型更聪明，也不自动赋予工具和权限。
- **知识库** 是长期资料集合；**RAG** 通常是先检索相关材料再生成回答。资料可能错、检索可能漏，仍需核验。
- **Workflow** 是动作的顺序、条件与交接；**自动化** 按时间或事件触发稳定流程。普通对话没有调度能力就不能定时运行。
- **API** 是程序调用服务的接口，聊天会员、API 额度与部署费用可能分开，需按提供方核实。密钥是凭证，不是提示词素材。
- **MCP** 是 Agent 连接工具/数据的一种协议，需宿主支持、连接服务和授权。不要求新手先配置一套。
- **云端/本地** 区别在运行位置；本地流程仍可能调用外部接口、搜索或遥测，隐私取决于全链路。
- **Vibe Coding** 在本课指通过自然语言与编程 Agent 合作做应用，人负责目标、范围和验收，不是一次生成任意可靠系统。

## 路线

办公：通知/纪要 → 需求与资料 → 文档/表格/PPT → 修改核验 → 方法复用。

内容：事实材料 → 对象与格式 → 草稿 → 对照修改 → 可复用任务说明。不编造业绩或用户见证。

应用：目标 → 最小输入输出 → 简短 PRD → 运行功能 → 测试 → 保存与分享。API/MCP 等到任务需要时再讲，不作为入门门槛。

没有目标从 [文字任务课](lessons/text.md) 示范；PPT 需求用 [PPT 课](lessons/ppt.md)；应用用 [项目课](lessons/vibe-coding.md)。

## 完成标准

基础任务要有需求、可追溯结果、人工核对和修改；相似新任务独立做过才算迁移。应用要运行并测正常/异常/重复操作与保存，截图不代替功能测试。分享须按接收方式独立验证，只有本机证据就只说本机可用。产物完成与学员掌握分别记录。
