# Vibe Coding 项目课

以下需求是教学示例，不预设为用户要求。用户想先看示范可用此例；已有自己目标则按其目标调整。


### 最小需求与 PRD 示例

教学样例：本人在电脑浏览器使用的待办页，输入文字添加事项，能标记完成；首版不需要账号、联网模型、多人同步和支付。

约定：文字去掉首尾空白后不能为空；单项不超过 100 个字符；刷新后保留数据；每次有效提交新增一条，允许相同文字表示两件同名事项；添加成功清空输入框；使用浏览器本地保存，换设备不自动同步。以上为示例产品决策，应随学员真实目标调整。

页面只需标题、输入区、添加按钮、待办列表和完成状态。第一步完成添加与展示，第二步完成状态与保存。老师可在授权内连续构建和检查，学员想学时解释关键选择，不要求每一步回复“继续”。

### 验收样本

| 操作 | 预期 |
|---|---|
| 输入“准备材料”并添加 | 出现一条相同文字事项，输入框清空 |
| 输入空白或空格 | 不新增事项，给可理解提示 |
| 输入 101 个字符 | 明确提示长度限制，不默默保存不完整内容 |
| 添加后直接再次点击 | 因输入已清空，不增加空事项 |
| 再输入同样文字提交 | 按示例约定新增同名事项，不擅自去重 |
| 切换完成状态后刷新 | 文字和状态仍保留 |
| 换浏览器或设备 | 不承诺看见原数据；解释本地保存边界 |

### 修复、交接与分享

出错时收集复现步骤、期望与实际、截图或错误文字。相同修复连续失败两次后重新诊断，需换模型时携带目标、事实、已有改动、失败记录、可恢复版本和待验证问题。

发布前让学员决定是仅本机用、分享文件还是公开托管。每一种给对应实际说明，不默认公开部署；只有独立接收者或环境完成验证后才宣称可分享。教师构建成功可记为“示范已完成”，学员独立添加新需求并验收后再更新能力状态。
